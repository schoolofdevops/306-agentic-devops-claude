Course Architecture and Getting Started

How each module works​

Every module follows the same structure. Six videos, one consistent pattern:

#VideoFormatWhat it does
0Module IntroTalking headWhat you will learn and why it matters at work
1Concept explainerSlides + voiceoverThe ideas, with analogies before definitions
2Deep diveScreencast + concept slidesAdvanced walkthrough — under the hood
3Case studySlides + voiceoverReal-world application (where a marquee case exists)
4Lab walkthroughScreencastLive terminal demo of the lab
5Module SummaryTalking headKey takeaways and bridge to the next module

The lab is the proof. Every command is copy-runnable, every output block is from a real execution, and a deterministic grader tells you whether you succeeded — no guesswork, no vibes.

The four phases​

The course is structured in four phases. Each phase earns the trust required for the next — you never skip a level of autonomy.

Phase 1: Foundation (Modules 1–4) — Manual → AI Augmented​

Module 1 establishes the manual baseline — you run the full repair loop by hand. Modules 2–4 introduce Claude Code as your assistant while you stay in full control.

ModuleFocus
M1The repair loop — manual baseline: diagnose, change, verify
M2Install, permission postures, and sandboxing
M3Context engineering, bounded evidence, and operational memory
M4Model selection, effort tuning, and cost engineering

Phase 2: Agentic Foundations (Modules 5–9) — Agent Proposes, You Approve​

Skills, subagents, and structured loops where the agent has agency but you hold the approval gate (semi-autonomous).

ModuleFocus
M5The plan, execute, verify, goal loop
M6Skills — runbooks compiled into reusable procedures
M7Tool interface engineering — CLI first, MCP when it earns the boundary
M8Hooks, policy gates, GitOps, and the environment contract
M9Role-specific DevOps subagents with scoped authority

Phase 3: Domain Application (Modules 10–16) — Agentic at Scale​

Orchestration topologies, agentic teams, and domain-specific workflows operating within governed guardrails — moving toward the autonomous end of the spectrum.

ModuleFocus
M10Orchestration topologies — fan-out, pipeline, synthesis, judge panels
M11AI-augmented IaC and FinOps
M12Containers, Kubernetes, and GitOps
M13CI/CD and release engineering
M14SRE, observability, and incident response
M15SecOps and action-boundary engineering
M16Optional: MLOps and LLMOps

Phase 4: Production (Modules 17–19) — Full Operating Layer​

Event-driven agents, evaluation, and the capstone compound incident.

ModuleFocus
M17Reliable automation, events, and always-on patterns
M18Observe, evaluate, and control the agents
M19Capstone: campaign incident, packaging, and rollout

Cost expectations​

Running the labs requires compute for containers, a local Kubernetes cluster (kind), and Claude Code API usage.

Machine requirements:

  • 16 GB RAM (recommended): Full kind cluster + Argo CD + lightweight metrics. All labs run natively.
  • 8 GB RAM (supported): Staged low-memory profiles and evidence fixtures where the full stack is too heavy. The learning outcomes are identical — you work with real but lighter infrastructure.

Claude Code costs:

  • Modules 1–4 use minimal tokens — short, scoped interactions.
  • Modules 5–9 increase as you use subagents and structured loops.
  • Modules 10–19 involve orchestration and multi-agent workflows — token usage scales with complexity.
  • Expect $5–15 total across the full course at standard model pricing. Cost engineering (Module 4) teaches you how to control this.

Optional tracks​

Not every module is required for every learner:

  • Module 16 (MLOps/LLMOps) is explicitly optional — take it if your work involves ML pipelines or LLM deployment.
  • Modules 10–16 can be taken in any order within the phase — each applies the skills from Phases 1–2 to a different domain.
  • The capstone (Module 19) assumes all prior modules.

Getting started​

  1. Complete the Setup section — install prerequisites and verify your environment.
  2. Clone the lab repository: 306-agentic-devops-claude-labs.
  3. Start with Module 1 — the repair loop on Northstar Commerce.
